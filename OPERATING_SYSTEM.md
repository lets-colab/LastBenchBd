## 3. Human operating loop

The default company loop is:

**OFFICE → ONE Main → real source record → execute → proof → update the same task → Daily Close → Co.MPASS**

1. Open **OFFICE — Company OS** in Notion.
2. Select one real **Main** task from the Action Board.
3. Open the authoritative student, learner, lead, partner, business or project record.
4. Execute the work in that source system.
5. Attach or link verifiable proof.
6. Update the same Notion task with status, next step, date and proof.
7. Use Slack only to communicate decisions, receipts, blockers and exceptions.
8. Let Co.MPASS summarize governed evidence; do not manually recreate the record in Co.MPASS.

Do not create a second CRM, task database or customer list because a view is inconvenient.

A mirror is acceptable only when automated or clearly labelled partial/read-only.

## 5. Truth and execution states

### Truth state

- **ACTUAL** — directly supported by current evidence.
- **TARGET** — an intended goal.
- **FORECAST** — a reasoned future estimate.
- **UNKNOWN** — evidence is insufficient or unavailable.

### Execution state

**PLANNED → BUILT → TESTED → LIVE → PROVEN**

Never compress these states. In particular:

- BUILT ≠ TESTED
- TESTED ≠ LIVE
- LIVE ≠ PROVEN
- registration ≠ paid learner
- contact ≠ deal
- proposal ≠ revenue
- MOU ≠ producing partner
- database zero ≠ proof of zero real-world activity

## 6. Co.MPASS contract

Co.MPASS is the company intelligence interface, not the system of record.

It should answer five questions:

1. **ROOM — What is true now?**
2. **MAP — How is the company structured?**
3. **FOCUS — What matters next?**
4. **DETOUR — What is blocked or conflicting?**
5. **TIME MACHINE — What changed, with evidence?**

Every material observation should retain:

- source;
- observed time;
- owner;
- truth state;
- execution state;
- evidence reference;
- visibility/permission boundary.

Historical corrections append new evidence; they do not silently rewrite history.

## 7. DR.X governance layer

DR.X is the governing intelligence and routing layer above the tools.

DR.X should:

- retrieve authoritative sources before reconstructing from memory;
- distinguish ACTUAL, VERIFIED, HISTORICAL, SIMULATED, INFERRED, PLANNED and UNVERIFIED;
- select the smallest evidence-backed reversible action;
- preserve approval gates for consequential, destructive, security, financial and permission changes;
- use Co.MPASS for company state, not as a substitute for source systems;
- preserve the canonical brand locks and business architecture;
- record failures, fixes and recurring patterns for governed self-healing.

Scenario or simulation systems such as MiroFish must never be promoted to ACTUAL evidence.

## 8. Team cadence

The intended operating rhythm is:

- **Morning:** choose the Main work from the canonical Action Board/source record.
- **During work:** update the authoritative record, not a parallel report.
- **Daily Close:** record what changed, proof, blocker and next step on the same work item.
- **Monday 09:00 Asia/Dhaka:** opportunity radar where the automation/workflow is enabled and verified.
- **Friday 18:00 Asia/Dhaka:** research shortlist feeding the capability/strategy system where enabled and verified.
- **CLASS[Λ] learning cadence:** separate from the company operating record; course delivery/lessons should remain in the CLASS[Λ] workspace.

Cadence language is a target operating contract. Any automation remains **UNVERIFIED** until a real end-to-end run is observed.

## 10. Non-negotiable operating rules

1. **One source record per real object.**
2. **One current owner per active item.**
3. **One next action and date.**
4. **Proof before status inflation.**
5. **Slack communicates; it does not become the database.**
6. **Notion organizes work; it does not duplicate the CRM.**
7. **Co.MPASS observes governed evidence; it does not invent it.**
8. **Miro explains; it does not hold truth.**
9. **GitHub controls canonical product, brand and technical documentation.**
10. **If a source is stale, conflicting or unhealthy, surface the conflict rather than guessing.**

## 11. Source-of-truth order

3. `PRODUCT.md` for business/product architecture.
4. `OPERATING_SYSTEM.md` for company operating law.
5. `brand/last-bench/BRAND_BLUEPRINT.md` and locked brand assets for identity.
6. `FOUNDATION_LOCK.md` / migration ledger for technical production truth.
7. Current Notion OFFICE/Co.MPASS views for human-facing operation.

9. Historical profiles, decks, screenshots and archived handoffs.

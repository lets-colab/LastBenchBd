# CLASS[Λ] — Canonical Brand Blueprint

Status: **canonical capability-brand reference**  
Parent ecosystem: Last Bench  
Implementation namespace: `landing/class-a/`

## 1. Brand definition

**Name:** CLASS[Λ]  
**Role:** Capability accelerator / one-person venture-building engine  
**Current identity line:** **ACQUIRE. APPLY. ADVANCE.**

CLASS[Λ] is designed to move a learner from AI beginner toward a venture-ready founder through practical capability, proof-of-work, systems, prompting, tools, automation and execution.

## 2. Product architecture

### Class 0 / Free Masterclass

A free entry point that introduces the operating model and routes qualified learners into the full program.

### Full program

The current production funnel positions the paid offer as a **20-Class One-Person Venture Builder** with proof-of-work outcomes.

The visual system must support conversion without becoming a generic course-marketing template.

## 3. Core visual DNA

CLASS[Λ] is visually independent from Last Bench parent marketing.

Use:

- near-black cinematic canvas;
- editorial white/off-white typography;
- neutral graphite/silver materials;
- **smoked translucent glass UI planes with neon-green edge light**;
- original brand green `#00C853` as the primary energy color and `#00E676` only as a bright edge/highlight state;
- strong negative space;
- technical/grid texture kept extremely subtle;
- controlled depth, perspective and orbital geometry;
- restrained glass reflections, blur and green luminous depth;
- a premium technical/editorial feel.

The current locked material direction is **neon glassy green 3D**: dimensional smoked glass, precise green light, metallic/silver capability objects and black space. It must not become a generic cyberpunk/neon gaming interface.

Do **not** automatically apply Last Bench green/white marketing styling to CLASS[Λ].

## 4. Signature hero system

Current locked direction includes:

- **ONE PERSON. A FULL AI TEAM.**
- **AI BEGINNER → VENTURE-READY FOUNDER**
- dimensional floating **20** object;
- restrained orbital rings;
- cinematic depth and parallax;
- conversion-first CTA.

The floating 20 and orbital system should feel like an AI operating system, not a game UI or decorative gimmick.

## 5. Logo system

Canonical files in this folder:

- `class-a-logo.jpg`
- `class-a-favicon.jpg`
- `last-bench-parent-mark.png` — parent endorsement mark only

Exact fingerprints are stored in `brand-lock.json`.

### Non-negotiable

- Never redraw or regenerate the CLASS[Λ] logo.
- Never approximate the Λ or wordmark using a random font.
- Never replace the source logo with an AI-generated version.
- Keep the Last Bench parent mark separate; do not merge it into a new hybrid logo.

## 6. Typography and hierarchy

The hero typography is the dominant graphic device.

- preserve aggressive scale;
- preserve intentional mobile line breaks;
- keep supporting copy materially quieter;
- do not shrink the hero merely to make layout easier.

If a precise font file is not canonically available, preserve the existing implementation rather than inventing a new brand typeface.

## 7. Motion

Allowed:

- slow physical float;
- subtle orbital movement;
- restrained camera/parallax;
- staggered editorial reveals;
- meaningful CTA state changes.

Avoid:

- bouncy motion;
- neon overload;
- particle-heavy effects;
- playful game-like animation.

Always respect `prefers-reduced-motion`.

## 8. Conversion and truth

The cinematic system must never obscure the offer.

- Free masterclass must stay explicitly free.
- Paid program price/copy must come from current approved production truth.
- Never add dates unless explicitly approved.
- Never manufacture outcomes, testimonials, cohort sizes, revenue or employment claims.

## 9. Production release gate

CLASS[Λ] is not visually approved merely because the build or deployment succeeds.

Required:

1. exact logo asset;
2. visual comparison against the approved cinematic source;
3. mobile and desktop QA;
4. functional form/CTA verification;
5. accessibility and reduced-motion checks;
6. saved/live artifact inspection.

The mandatory visual guardrail remains:

`skills/class-a-visual-source-lock/SKILL.md`

## 10. Outbound email design lock — CLASS[Λ] × LAST BENCH

**Owner-approved:** 18 October 2026. **Scope:** CLASS[Λ] transactional and lifecycle email only; not the Last Bench corporate site, Education & Mobility, co.lab, or other brands. This section is the canonical design rule for future CLASS[Λ] email drafting, HTML template changes, email previews, and branded email PDF attachments. Supersede this visual system only with explicit new owner approval.

### Visual reference and appearance

Approved design family: the October 2026 emails **Application Received**, **Personal Course Quotation**, and **Course Registration Confirmed**, supplied as screenshots by the owner. Screenshots are visual references, **not** downloadable source HTML or authority for a recipient's current application, enrollment, fee, payment, or seat status.

- **Outer canvas:** dark charcoal (target `#222525`); **inner body/card:** near-black (`#101110`) with substantial breathing room and soft rounded corners; **top stripe:** solid **Brand Green `#00C853`**.
- **Headline:** dominant, editorial, bold, white, uppercase, tight line breaks. **Eyebrow:** small uppercase tracking with muted green accents; brand header reads `CLASS[Λ] × LAST BENCH` or uses exact separately locked assets when embedded. Do not type-approximate the official logo as a replacement asset.
- **Body:** restrained warm/off-white and neutral gray on dark background; meaningful paragraph spacing; personalized salutation. Do not use a light/white email body as the primary layout.
- **Status, price, and reference cards:** deep green-charcoal panel (target `#1C2620`), high-contrast white primary value and green field labels. Put critical status and terms in readable **text**, never image-only artwork.
- **Action:** a single dominant `#00C853` CTA where an action is justified; descriptive text, generous padding and a clear destination. Footer retains the CLASS[Λ] and Last Bench relationship, help contact, and required operational/legal details.
- **Email design tokens:** fixed Brand Green `#00C853`; other hex values above are **implementation targets derived from visual references**, not claimed measured values or replacements for the locked brand assets. Avoid gradients, gratuitous 3D, large animations, or web-only effects in email.

### Required message families and evidence semantics

| Message | Accurate permitted status | Prohibited inference |
| --- | --- | --- |
| **Application Received** | Application actually recorded; verified application reference; acceptance and payment handled separately | No promise that a seat is confirmed or money received |
| **Personal Course Quotation** | Approved current offer, fee, validity and payment instructions, with clearly labeled quote PDF if used | A quotation is **not** an invoice, receipt, registration, or payment verification |
| **Course Registration Confirmed** | Only state confirmed when the authoritative registration/acceptance record authorizes it; communicate schedule only if verified | Do not turn mere application receipt into confirmed admission |
| **Invoice / Payment Request** | Properly identified invoice number, issue date, due date if applicable, correct billing party, current approved fee, and verified payment method | A bill is not proof of payment; never publish a guessed account/payee |
| **Payment Verified / Receipt** | Only after verified financial evidence, with payment record reference, paid amount, payment method, and separate seat status; receipt PDF when generated | Payment does not automatically confirm admission or establish bank reconciliation |
| **Reminders / Onboarding / Updates** | Current verified stage, action, date/time/timezone, and approved link as relevant | Do not invent schedules, deadlines, attendance, outcomes or statuses |

All financial details (including any prior `BDT 5,000` quote or prior bKash instructions), dates, names, account details, application numbers, and cohort status shown in the historical examples are **dated examples**, **not evergreen template constants**. Resolve live values from the current authorized record at send time. Never copy another learner's details. Escape user-derived HTML, and preserve transaction-state guards and idempotency.

### Email production and send gate

1. Use **email-compatible table-based HTML and inline CSS**, responsive single-column content (maximum ~600px), ~16–28px content gutters, legible mobile type, ~44px touch targets, and meaningful alt text for approved image assets; include a plain-text alternative.
2. Ensure sufficient contrast and readable output when images are blocked, dark-mode clients override colors, or CSS is partially stripped. Do not make a claim or action available only through an image.
3. Reuse exact approved CLASS[Λ]/Last Bench image files and brand-lock fingerprints. Never trace/redraw/recolor marks or invent a combined logo. Signed-off PDF artifacts inherit the same hierarchy and color language but have their own invoice/receipt truth checks.
4. Before any template rollout, check visual parity with the approved screenshots on mobile Gmail and a desktop mail client, test fallback/CTA/attachments, and run message-specific state tests. Preserve the sender, recipient, retry/deduplication, consent, delivery-evidence, and financial safeguards.
5. **Documentation lock is not rollout proof.** Existing email worker code may differ from this approved dark style; changing this rule alone does not alter a deployed worker or guarantee delivered emails use it. Mark runtime adoption `UNVERIFIED` until template code, checks, deployment and an actual authorized delivery are independently verified. No live messages or payment records are authorized by this design approval.
